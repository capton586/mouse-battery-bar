# 给自己的鼠标换一个读取器

1. 确认鼠标底部的完整型号、连接方式和固件版本（若可见）。在 macOS 的蓝牙、电池或设备信息中检查系统是否已提供该设备的电量。系统能给出电量时优先使用它。USB、有线、蓝牙可以对应不同标识、接口和协议。
2. USB 接收器可用 `hidutil list` 查厂商号、产品号和用途。同名接口很常见；用 HID 描述符或该型号的协议资料确认电量所在接口。检查电量属于目标鼠标，尤其注意耳机、键盘和笔记本自身的百分比。只记录验证所需的设备信息。
3. 在 `src/MouseProfile.m` 实现 `MouseName` 与 `ReadBattery`。成功时返回 nil 并填入 0–100 的新读数；失败时返回可显示的原因。对型号、报告类型、长度和范围作校验。没有可验证的协议时，保留“不支持”，不要填示例值。只有真实的 0% 才显示 0%。
4. 用自己的 bundle ID 替换 `Info.plist` 中的 `CFBundleIdentifier`，让 macOS 分开保存权限与偏好。运行构建脚本，再用 README 中的 `--print` 检查结果。唤醒鼠标并采几次，与官方工具或设备灯色交叉对照。灯色只能验证区间。拔出接收器、让鼠标休眠、重新接回，检查失败、过期读数和恢复。最后双击应用，验证菜单栏、立即刷新和采样间隔。
5. 需要回报率、DPI 或侧键时，先确认该鼠标相应的字段及协议，区分读取和写入。增加写入功能前，保存原值、验证可恢复，并对每个值做写后回读。电量采样间隔（分钟）、鼠标回报率（Hz）、DPI 是三个独立设置。

## 已验证实例

雷柏 VT9PRO，接收器 `24ae:185a`。本机的厂商报告与键盘集合共用同一 HID 接口。以共享模式打开，只解析输入报告 `0xBB`，不发送配置命令。该设备示例报告 `BB B0 42 00 19 01 35` 的末字节 `0x35` 表示 53%。有的 macOS 回调在数据前附加报告 ID，有的单独传递 ID，需要根据长度处理。等待新报告最多 14 秒，每次读取结束释放接口。相同品牌或系列名称不足以证明协议兼容。

报告字段参考：[Device Battery Tray 的 read_rapoo 实现](https://github.com/Tsifrokayf/Device-Battery-Tray/blob/main/lamzu_tray.py)。本仓库使用原生 IOKit 独立实现。
